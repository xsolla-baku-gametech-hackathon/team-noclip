2.1. PRIMARY RECAP SYSTEM PROMPT (Strict Schema & Anti-Hallucination)
--------------------------------------------------------------------------------
ROLE:
You are the Xsolla Game Recap engine for Stardew Valley. Your role is to act as
a personalized, context-aware memory bridge for a player returning to their farm
after weeks or months away. You eliminate resumption friction in under 10 seconds.

STRICT FACTUAL GROUNDING RULES:
1. ZERO HALLUCINATION: Only use facts explicitly provided in the input JSON.
2. NEVER invent quests, items, villagers, seasons, dates, or crop states.
3. NEVER assume the player owns an item or completed a task unless verified in the input.
4. If a field is missing, null, or empty, ignore it gracefully.
5. All IDs have been pre-resolved to human-readable names. Use only those names.

CONTENT CONSTRAINTS:
1. "previouslyOn": EXACTLY TWO SENTENCES.
   - Sentence 1: Remind the player of their current temporal and financial place 
     (e.g., "You returned to Misty Farm on Summer 18, Year 2, with 12,450g in savings.").
   - Sentence 2: Summarize current ongoing efforts or macro-level situation 
     (e.g., "Your farm is in the middle of harvest season while the Community Center awaits several key contributions.").
2. "criticalPriorities": EXACTLY THREE ITEMS (or fewer if fewer exist).
   - Priority hierarchy:
     * HIGH: Dead crops that need clearing; crops ready for harvest today; unwatered crops.
     * HIGH: Quests expiring today (daysLeft == 0) or tomorrow (daysLeft == 1).
     * HIGH: A villager's birthday occurring today or tomorrow.
     * MEDIUM: Active community center missing items that are in season.
     * MEDIUM: Villagers with low friendship hearts (<= 2) worth talking to.
     * LOW: Long-term farm goals and general milestones.
   - Each priority must have:
     * "title": Short action imperative (3-5 words max, e.g., "Harvest Ready Crops").
     * "description": One concise informative sentence with quantities.
     * "importance": "high" | "medium" | "low".
3. "goalTracker":
   - "activeQuests": Max 5 active quests formatted as "Title - X days left" (or "No time limit").
   - "missingBundleItems": Key missing items for the Community Center.
   - "milestones": Current overarching objectives (e.g., "Community Center: 18/30 bundles completed").
4. FORMAT:
   - Output MUST be valid, parseable JSON matching the schema exactly.
   - DO NOT include markdown fences (```json ... ```) or conversational commentary.

OUTPUT JSON SCHEMA:
{
  "success": true,
  "previouslyOn": "string (exactly 2 sentences)",
  "criticalPriorities": [
    {
      "title": "string",
      "description": "string",
      "importance": "high" | "medium" | "low"
    }
  ],
  "goalTracker": {
    "activeQuests": ["string"],
    "missingBundleItems": ["string"],
    "milestones": ["string"]
  }
}

2.3. HEURISTIC / DETERMINISTIC FALLBACK PROMPT (Offline / Timeout Engine)
--------------------------------------------------------------------------------
When LLM call fails, times out (>5s), or rate limits occur, the middleware 
executes a pure Python deterministic generator:

```python
def generate_heuristic_recap(state: GameStateDto) -> RecapResponseDto:
    # 1. Previously On:
    p1 = f"You returned to {state.player.farm_name} in {state.date.season} of Year {state.date.year} with {state.player.gold:,}g."
    p2 = f"You are managing {state.farm.crop_count} crops across the farm while progressing toward your village goals."
    previously_on = f"{p1} {p2}"
    
    # 2. Critical Priorities:
    priorities = []
    if state.farm.dead_crops > 0 or state.farm.ready_to_harvest > 0:
        priorities.append(PriorityDto(
            title="Tend to Harvest & Debris",
            description=f"{state.farm.ready_to_harvest} crops ready to harvest; {state.farm.dead_crops} dead crops to remove.",
            importance="high"
        ))
    if state.farm.needs_water > 0:
        priorities.append(PriorityDto(
            title="Water Your Crops",
            description=f"{state.farm.needs_water} crops need water before the day ends.",
            importance="high"
        ))
    if state.social.upcoming_birthdays:
        bday = state.social.upcoming_birthdays[0]
        priorities.append(PriorityDto(
            title=f"{bday.name}'s Birthday",
            description=f"{bday.name}'s birthday is coming up on {bday.birthday}.",
            importance="medium"
        ))
    elif state.active_quests:
        q = state.active_quests[0]
        priorities.append(PriorityDto(
            title=f"Quest: {q.title}",
            description=f"{q.description} ({'Expires today' if q.days_left == 0 else f'{q.days_left} days left' if q.days_left > 0 else 'No time limit'}).",
            importance="medium"
        ))
    elif state.community_center.missing_items:
        items = ", ".join(state.community_center.missing_items[:2])
        priorities.append(PriorityDto(
            title="Community Center Supplies",
            description=f"Work towards obtaining: {items}.",
            importance="medium"
        ))
    
    # Pad to 3 if needed
    if len(priorities) < 3:
        priorities.append(PriorityDto(
            title="Explore and Socialize",
            description="Visit Pelican Town to greet villagers and check Pierre's stock.",
            importance="low"
        ))

    # 3. Goal Tracker
    quests = [f"{q.title} ({q.days_left}d left)" if q.days_left >= 0 else q.title for q in state.active_quests[:5]]
    cc_items = state.community_center.missing_items[:5]
    milestones = [f"Community Center: {state.community_center.completed_bundles}/{state.community_center.total_bundles} Completed"]
    
    return RecapResponseDto(
        success=True,
        previously_on=previously_on,
        critical_priorities=priorities[:3],
        goal_tracker=GoalTrackerDto(
            active_quests=quests,
            missing_bundle_items=cc_items,
            milestones=milestones
        )
    )
```

3. PARSERS & RESOLVERS SPECIFICATIONS ("PARSE & APARSE")
================================================================================

In Stardew Valley 1.6, internal entities frequently use qualified item IDs 
(e.g., "(O)24" or "24" for Parsnip, internal quest IDs, unlocalized bundle strings).
Sending raw internal IDs to the LLM confuses the model.
We build four dedicated Resolvers/Parsers in the mod (and mirrored in Python).

3.1. CropResolver (`Extraction/CropResolver.cs`)
--------------------------------------------------------------------------------
PURPOSE:
Translates live `HoeDirt` and `Crop` instances into clean human-readable crop names
and accurate lifecycle status.

LOGIC:
1. Input: `HoeDirt dirt`, `Vector2 tileLocation`.
2. Extract Crop: `dirt.crop`. If `null`, skip.
3. Determine Name:
   - In Stardew Valley 1.6: `ItemRegistry.GetData(dirt.crop.indexOfHarvest.Value)?.DisplayName`
   - Fallback: `dirt.crop.indexOfHarvest.Value` mapped to known dictionary.
4. Determine Lifecycle State:
   - If `dirt.crop.dead.Value` -> `"dead"`
   - If `dirt.crop.currentPhase.Value >= dirt.crop.phaseDays.Count - 1` -> `"ready"`
   - If `!dirt.isWatered.Value` -> `"needs_water"`
   - If regrowable harvest available (`dirt.crop.fullyGrown.Value && dirt.crop.dayOfCurrentPhase.Value <= 0`) -> `"ready"`
   - Otherwise -> `"growing"`
5. Output: `CropDto { CropName, State, X, Y }`.

3.2. BundleParser (`Extraction/BundleParser.cs`)
--------------------------------------------------------------------------------
PURPOSE:
Parses Stardew 1.6 Community Center bundle structures without corrupting or breaking
across patch updates.

BACKGROUND:
- `Game1.netWorldState.Value.GetUnlocalizedBundleData()` returns dictionary of bundle keys.
- Bundle data format in Stardew:
  Format: `Name/Reward/Ingredients/Color/SpriteIndex/DisplayName`
  Ingredients format: `[ItemID] [Count] [Quality] ...`
- `CommunityCenter` location keeps track of `bundles.Pairs`:
  Boolean array of which ingredient slots are filled.

PARSING LOGIC:
1. Check if Community Center is completed:
   `Game1.MasterPlayer.hasCompletedCommunityCenter()` or `Game1.netWorldState.Value.VisitsUntilY1Guarantee.Value`
2. Iterate all bundles:
   - Identify which room it belongs to (Pantry, Crafts Room, Fish Tank, Boiler Room, Vault, Bulletin Board).
   - Read ingredient requirements: Each ingredient has `(ItemQualifiedId, RequiredQuantity)`.
   - Check slot completion in the bundle's `bool[]` array.
3. Map missing item IDs to localized item display names:
   `ItemRegistry.GetData(itemId)?.DisplayName ?? itemId`
4. Filter missing items relevant to the current season:
   If current season is "Summer", prioritize missing Summer crops/fish.
5. Output:
   `CommunityCenterDto { Complete, CompletedBundles, TotalBundles, MissingItems }`.

3.3. QuestResolver (`Extraction/QuestResolver.cs`)
--------------------------------------------------------------------------------
PURPOSE:
Interprets quest entries in `Game1.player.questLog` and `Game1.netWorldState.Value.SpecialOrders`.

BACKGROUND:
- Stardew quests inherit from `Quest`. Subclasses include:
  * `ItemDeliveryQuest`: target villager, item sought.
  * `SlayMonstersQuest`: monster target, count remaining.
  * `ResourceCollectionQuest`: resource ID, number collected.
  * `SocializeQuest`: intro quest to talk to townspeople.
  * `DescriptionElementList` holds dynamic text tokens.
- `daysLeft` is not universally a simple int on all quest types:
  * Regular billboard quests have `quest.daysLeft.Value`.
  * Special Orders have `order.dueDate.Value - Game1.Date.TotalDays`.
  * Story quests have no deadline -> Represent as `-1` (Indefinite/No time limit).

LOGIC:
1. For each `Quest q` in `Game1.player.questLog`:
   - Title: `q.questTitle` or clean class name fallback.
   - Description: `q.questDescription` or formatted objective.
   - DaysLeft: If `q.dailyQuest.Value`, use `q.daysLeft.Value`. Else `-1`.
   - IsSpecialOrder: `false`.
2. For each active `SpecialOrder order` in `Game1.player.team.specialOrders`:
   - Title: `order.GetName()`.
   - Description: `order.GetDescription()`.
   - DaysLeft: `Math.Max(0, order.dueDate.Value - Game1.Date.TotalDays)`.
   - IsSpecialOrder: `true`.
3. Output: `List<QuestDto>`.

3.4. SocialResolver (`Extraction/SocialResolver.cs`)
--------------------------------------------------------------------------------
PURPOSE:
Identifies high-priority social interactions so players don't miss friendship 
milestones or birthdays.

LOGIC:
1. Scan all active NPCs in `Game1.locations`:
   Filter: `npc.IsVillager && !npc.IsChild && !npc.IsMonster`.
2. Evaluate Friendship:
   `int hearts = Game1.player.getFriendshipHeartLevelForNPC(npc.Name);`
   If `hearts <= 2`, add to `LowHeartVillagers`.
3. Evaluate Birthdays:
   Check `npc.Birthday_Season == Game1.currentSeason`.
   If `npc.Birthday_Day == Game1.dayOfMonth` -> Birthday is TODAY!
   If `npc.Birthday_Day == Game1.dayOfMonth + 1` -> Birthday is TOMORROW!
   Add matching villagers to `UpcomingBirthdays`.
4. Output: `SocialDto { LowHeartVillagers, UpcomingBirthdays }`.

3.5. SaveXmlParser (Fallback Parser for Offline / Stale Saves)
--------------------------------------------------------------------------------
PURPOSE:
Allows running the recap engine against a saved file (`<PlayerName>_<SaveID>`)
directly without having Stardew Valley running. Ideal for:
- Automated backend testing
- Web dashboard or companion app view
- Fallback if runtime mod state fails to extract.

STRUCTURE OF STARDEW SAVE XML:
- Path: `%APPDATA%/StardewValley/Saves/<SaveName>/<SaveName>`
- Key XML Tags:
  * `<SaveGame>`
    * `<player>`: `<name>`, `<farmName>`, `<money>`, `<friendshipData>`
    * `<currentSeason>`, `<dayOfMonth>`, `<year>`, `<timeOfDay>`
    * `<locations><GameLocation xsi:type="Farm">`:
      `<terrainFeatures><item><value><TerrainFeature xsi:type="HoeDirt">`
    * `<communityCenter>`: `<bundles>`
    * `<questLog><Quest>`: active quests

PARSING STRATEGY:
- Implemented in Python (`backend/services/xml_parser.py`) using `defusedxml` / `xml.etree.ElementTree`.
- Converts XML tree into the exact same `GameStateDto` expected by the recap service.

```python
from pydantic import BaseModel, Field
from typing import List, Optional

class PlayerDto(BaseModel):
    name: str = ""
    farm_name: str = Field(default="", alias="farmName")
    gold: int = 0

class DateTimeDto(BaseModel):
    season: str = ""
    day: int = 1
    year: int = 1
    time_of_day: int = Field(default=600, alias="timeOfDay")

class FarmDto(BaseModel):
    crop_count: int = Field(default=0, alias="cropCount")
    ready_to_harvest: int = Field(default=0, alias="readyToHarvest")
    needs_water: int = Field(default=0, alias="needsWater")
    dead_crops: int = Field(default=0, alias="deadCrops")

class CropDto(BaseModel):
    crop_name: str = Field(default="", alias="cropName")
    state: str = "growing"
    x: int = 0
    y: int = 0

class CommunityCenterDto(BaseModel):
    complete: bool = False
    completed_bundles: int = Field(default=0, alias="completedBundles")
    total_bundles: int = Field(default=30, alias="totalBundles")
    missing_items: List[str] = Field(default_factory=list, alias="missingItems")

class QuestDto(BaseModel):
    title: str = ""
    description: str = ""
    days_left: int = Field(default=-1, alias="daysLeft")
    is_special_order: bool = Field(default=False, alias="isSpecialOrder")

class VillagerDto(BaseModel):
    name: str = ""
    hearts: int = 0
    birthday: str = ""

class SocialDto(BaseModel):
    low_heart_villagers: List[VillagerDto] = Field(default_factory=list, alias="lowHeartVillagers")
    upcoming_birthdays: List[VillagerDto] = Field(default_factory=list, alias="upcomingBirthdays")

class GameStateDto(BaseModel):
    player: PlayerDto = Field(default_factory=PlayerDto)
    date: DateTimeDto = Field(default_factory=DateTimeDto)
    farm: FarmDto = Field(default_factory=FarmDto)
    crops: List[CropDto] = Field(default_factory=list)
    community_center: CommunityCenterDto = Field(default_factory=CommunityCenterDto, alias="communityCenter")
    active_quests: List[QuestDto] = Field(default_factory=list, alias="activeQuests")
    social: SocialDto = Field(default_factory=SocialDto)

    class Config:
        populate_by_name = True
```

  Returns: `RecapResponseDto`
  Flow:
    1. Compute state hash = MD5(player.gold + date.day + season + cropCount).
    2. If hash in Cache and cache age < 60s -> return cached response immediately.
    3. Call `llm_service.generate_recap(state)`.
    4. If LLM fails or times out (> 4.0s), call `heuristic_service.generate_heuristic_recap(state)`.
    5. Cache and return.

- POST /api/recap/from-xml:
  Accepts: XML file upload or save path string.
  Returns: `RecapResponseDto`.

- GET /health:
  Returns: `{"status": "healthy", "llm_connected": true, "version": "1.0.0"}`.

6.2. Game State Extraction Best Practices
--------------------------------------------------------------------------------
- LIVE RUNTIME STATE FIRST: Access `Game1.player`, `Game1.getFarm()`, `Game1.netWorldState`
  directly rather than reading save files from disk.
- THREAD SAFETY: Game state extraction MUST occur on the game thread before dispatching
  the network call to `Task.Run`.
- SAFE DISPATCH: Network call runs in background task; results are stored in 
  `pendingResponse` and handed to `RecapModalMenu` inside `Events.GameLoop.UpdateTicked`.
