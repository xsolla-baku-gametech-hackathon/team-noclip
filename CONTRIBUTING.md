# Contributing Guidelines

Welcome to the Team Noclip repository! This document outlines the process for contributing to our codebase. Following these guidelines ensures that our workflow is smooth, teamwork is visible, and we maximize our score for the hackathon/competition.

## General Workflow

1. **Find or Create an Issue:** Before writing code, ensure there is an issue tracking the work. We use issues to track feature requests, bug fixes, and general tasks. Use the appropriate issue template.
2. **Assign Yourself:** If you are picking up an issue, assign yourself to it.
3. **Create a Branch:** Create a branch for your work. Use the following naming convention:
   - `feature/<issue-number>-<short-desc>` (e.g., `feature/12-add-login`)
   - `bugfix/<issue-number>-<short-desc>` (e.g., `bugfix/15-fix-crash`)
   - `chore/<issue-number>-<short-desc>` (e.g., `chore/2-update-readme`)
4. **Commit Often:** Make small, logical commits with clear commit messages. This shows continuous teamwork and effort.
5. **Open a Pull Request (PR):** When your work is ready (or even when it's still a Draft and you want feedback), open a PR against the `main` branch.
   - Fill out the PR template.
   - Link the PR to the relevant issue (e.g., `Closes #12`).
6. **Code Review:** Request a review from at least one teammate. Teamwork is key!
7. **Merge:** Once approved and tests pass, merge the PR and delete the branch.

## Commit Messages

Write clear and descriptive commit messages. 

Good:
> Add login button to the website header

Bad:
> fixed stuff

## Repository Structure

- `website/`: Contains all code for the project website.
- `games/`: Contains the games we support/develop.
- `.github/`: Contains templates for issues and PRs.

Thank you for contributing!
